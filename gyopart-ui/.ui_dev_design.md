# gyopart UI redesign — design

Ground-up redesign (user, 2026-10-12): the current UI is hard to navigate, only does part lookup for a picked
vehicle, never shows the interchange, and never reached junkyard inventory. Stack stays React + Vite + Tailwind
(existing `gyopart-ui`); the code is rewritten, not patched.

## What is this system for?

Find a used part I need, know every vehicle it interchanges with, and see which junkyard near me has one of those
vehicles sitting in a row right now.

## What does the user do 80% of the time?

Start from a need — "I need a <part> for my <vehicle>" or "I have part number X" — and end at "row 24 at US Auto,
a 2011 Sebring that arrived Tuesday". Part → interchange → yard availability is the hero flow.

## Hero surface

The **part page**: part identity (number, name, description, diagram thumbnail) at top; the interchange chart
(every vehicle using this part, grouped make → model with year ranges and trim/engine) and the **yard availability**
list (yards in radius with a matching vehicle, nearest/home yard first, row + arrival date + color, map link) side
by side or stacked. Everything else exists to get the user onto a part page quickly.

## What the system already knows (never ask for it)

- The user's vehicles (garage, persisted) and the active one.
- Home ZIP + radius, and the home yard (US Auto Supply, Sterling Heights) — set once.
- The car's full catalogue: categories → named subcategories → diagrams with callouts → parts.
- For any part: its full fitment (car_parts) → the interchange chart needs no input.
- Yard inventory with arrival dates → "new arrivals" needs no input.

## Data available (dev DB, 2026-10-12)

parts_interchange: 43,792 cars, 2.8M parts, 82.5M car↔part fitments, 8.7M diagrams (9,349 named subcategories),
6.1M images. junkyard_inventory: ~19k active vehicles across 5 sources.

## Blocker found

Yard ↔ catalogue matching goes through `vehicles.car_id`, set by the VIN/YMM mapping pipeline. Every vehicle
scraped in October has `car_id` NULL (pic_n_pull 0/12,691, us_auto_supply 0/1,092, parts_galore 0/1,063,
ryans 0/17); only May's ipullupull data was resolved (3,754/4,230). Until the pipeline runs on new scrapes, yard
availability on the part page will be empty for every yard that matters. Must be fixed for workflows 4 and 6.

## Approved workflows (user, 2026-10-12)

User changes to the draft: no free-text part search detached from categories (annoying in practice); categories
always visible, and a part filter shows each hit under its category before selecting; after selecting a part show
its diagram and part photos with buttons to the next steps, so the user verifies (or changes) the selection
before moving on; VIN optional, and when given, an NHTSA decode verifies the picked vehicle.

1. **Garage** — add a vehicle by year → make → model → trim → engine (searchable comboboxes); VIN optional: when
   entered, decode via NHTSA and show where it agrees/disagrees with the picked vehicle. Several vehicles; switch
   the active one from the top bar.
2. **Find a part on my vehicle** — category tree always visible (category → named subcategory). A filter box
   narrows the tree: matches are shown nested under their category/subcategory, never as a flat list. Diagrams
   zoom; callouts click through.
3. **Confirm the part** — selecting a part shows its diagram (callout highlighted) and its photos, with the part
   number, names and description; actions: "Interchange" / "Find in yards" to proceed, or back to change the pick.
4. **Interchange chart** — every vehicle using the part, grouped make → model with year ranges and trims/engines.
5. **Find it in a yard** — yards within radius of home ZIP holding an interchangeable vehicle, home yard (US Auto)
   pinned first; row, arrival date, color, map link.
6. **Look up a part number** — global box takes an OEM part number from anywhere → straight to step 3 for it.
7. **Browse a yard** — a yard's inventory, new arrivals first, filter by make/model/year; a vehicle → its
   catalogue (step 2 for that car).

Navigation: one top bar — part-number box, garage switcher, Yards. Everything else is reached from a vehicle or a
part, not from menus.

## Prereq: live VIN resolution (agreed 2026-10-12)

- Always-on worker, `vehicles` table as the queue (claim unresolved rows `FOR UPDATE SKIP LOCKED`, ≤50 VINs per
  NHTSA batch call); new yard cars resolve within ~a minute of the scrape writing them.
- `vin_cache` keeps the **full NHTSA record** (raw JSON) so processing logic can change and re-derive from source
  without re-fetching (user).
- Decode fields (engine displacement/cylinders, drive, fuel, body, trim) copied onto the vehicle; matching narrows
  to trim/engine where it can; when it cannot pick one car it stores the candidate set and the UI shows "likely"
  instead of "exact". Fallback fuzzy YMM match + discrepancies unchanged.
- Schema change to junkyard_common approved (new package version + migration on prod).
- US Auto Supply Sterling Heights ZIP: 48314 (user).
