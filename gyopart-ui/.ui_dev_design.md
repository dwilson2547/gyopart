# gyopart UI redesign — design

Ground-up redesign (user, 2026-10-12): the current UI is hard to navigate, only does part lookup for a picked
vehicle, never shows the interchange, and never reached junkyard inventory. Stack stays React + Vite + Tailwind
(existing `gyopart-ui`); the code is rewritten, not patched.

## What is this system for?

Find a used part I need, know every vehicle it interchanges with, and see which junkyard near me has one of those
vehicles sitting in a row right now.

## What does the user do 80% of the time?

Start from a need — "I need a <part> for my <vehicle>" or "I have part number X" — and end at "row 24 at US Auto,
a 2011 Sebring that arrived Tuesday". Part → interchange → yard availability is the hero flow.

## Hero surface

The **part page**: part identity (number, name, description, diagram thumbnail) at top; the interchange chart
(every vehicle using this part, grouped make → model with year ranges and trim/engine) and the **yard availability**
list (yards in radius with a matching vehicle, nearest/home yard first, row + arrival date + color, map link) side
by side or stacked. Everything else exists to get the user onto a part page quickly.

## What the system already knows (never ask for it)

- The user's vehicles (garage, persisted) and the active one.
- Home ZIP + radius, and the home yard (US Auto Supply, Sterling Heights) — set once.
- The car's full catalogue: categories → named subcategories → diagrams with callouts → parts.
- For any part: its full fitment (car_parts) → the interchange chart needs no input.
- Yard inventory with arrival dates → "new arrivals" needs no input.

## Data available (dev DB, 2026-10-12)

parts_interchange: 43,792 cars, 2.8M parts, 82.5M car↔part fitments, 8.7M diagrams (9,349 named subcategories),
6.1M images. junkyard_inventory: ~19k active vehicles across 5 sources.

## Blocker found (resolved 2026-10-12)

Yard ↔ catalogue matching needed `vehicles.car_id`, which nothing was setting for October scrapes. Fixed by the
live VIN resolver (below): vehicles now carry `car_id_candidates`, and search matches by overlap (exact/likely).

## Approved workflows (user, 2026-10-12)

User changes to the draft: no free-text part search detached from categories (annoying in practice); categories
always visible, and a part filter shows each hit under its category before selecting; after selecting a part show
its diagram and part photos with buttons to the next steps, so the user verifies (or changes) the selection
before moving on; VIN optional, and when given, an NHTSA decode verifies the picked vehicle.

1. **Garage** — add a vehicle by year → make → model → trim → engine (searchable comboboxes); VIN optional: when
   entered, decode via NHTSA and show where it agrees/disagrees with the picked vehicle. Several vehicles; switch
   the active one from the top bar.
2. **Find a part on my vehicle** — category tree always visible (category → named subcategory). A filter box
   narrows the tree: matches are shown nested under their category/subcategory, never as a flat list. Diagrams
   zoom; callouts click through.
3. **Confirm the part** — selecting a part shows its diagram (callout highlighted) and its photos, with the part
   number, names and description; actions: "Interchange" / "Find in yards" to proceed, or back to change the pick.
4. **Interchange chart** — every vehicle using the part, grouped make → model with year ranges and trims/engines.
5. **Find it in a yard** — yards within radius of home ZIP holding an interchangeable vehicle, home yard (US Auto)
   pinned first; row, arrival date, color, map link.
6. **Look up a part number** — global box takes an OEM part number from anywhere → straight to step 3 for it.
7. **Browse a yard** — a yard's inventory, new arrivals first, filter by make/model/year; a vehicle → its
   catalogue (step 2 for that car).

Navigation: one top bar — part-number box, garage switcher, Yards. Everything else is reached from a vehicle or a
part, not from menus.

## Prereq: live VIN resolution (agreed 2026-10-12)

- Always-on worker, `vehicles` table as the queue (claim unresolved rows `FOR UPDATE SKIP LOCKED`, ≤50 VINs per
  NHTSA batch call); new yard cars resolve within ~a minute of the scrape writing them.
- `vin_cache` keeps the **full NHTSA record** (raw JSON) so processing logic can change and re-derive from source
  without re-fetching (user).
- Decode fields (engine displacement/cylinders, drive, fuel, body, trim) copied onto the vehicle; matching narrows
  to trim/engine where it can; when it cannot pick one car it stores the candidate set and the UI shows "likely"
  instead of "exact". Fallback fuzzy YMM match + discrepancies unchanged.
- Schema change to junkyard_common approved (new package version + migration on prod).
- US Auto Supply Sterling Heights ZIP: 48314 (user).

## Visual direction (user, 2026-10-12: "like the theme of photo dump")

Borrow photo-dump's look (`media/photo-dump/photo-dump-ui/src/styles.scss`, `app.component.scss`), translated to
Tailwind v4 tokens:
- Colour tokens on `:root` / `[data-theme=dark]`: bg `#f4f5f7`/`#121316`, surface `#fff`/`#1b1d21`, text
  `#1f2328`/`#e6e7ea`, muted `#6b7280`/`#9aa0a8`, border `#dde1e6`/`#30343a`, hover 6–7% overlay, one accent
  `#0d6efd`/`#5b9bff`, danger `#dc3545`/`#ff6b78`. Components use only tokens.
- Theme: System → Light → Dark cycle button in the app bar, saved in localStorage, applied by an inline script in
  `index.html` before React boots (no light flash).
- Shell: 3.25rem app bar on surface with a 1px bottom border; breadcrumb-style title ("gyopart › 2011 Sebring");
  round 2.5rem icon buttons; content area scrolls, the page never does.
- Side drawer (22rem; full-width on phones) for the category tree, like photo-dump's nav drawer: uppercase
  0.72rem muted section labels, 0.5rem-radius nav items, search box with leading icon + clear button.
- Pills/chips (999px radius, 1px border; accent-filled when on) for filters and exact/likely badges.
- Empty states: centred muted icon + one line + a hint line.
- Icons: lucide-react (already a dependency; photo-dump uses bootstrap-icons — same weight/feel).

## Workflow Requirements

Shared, held in the app (not asked again): garage (vehicles with year/make/model/trim/engine names + car_id,
optional VIN + its decode summary), active vehicle id, home ZIP (default 48314), radius (default 50 mi), theme.
Persisted in localStorage (single-user app, no accounts); every read try/catch, the app works with it empty.

### 1. Garage
- **Shows:** list of saved vehicles ("2011 Chrysler Sebring · Touring · 2.4L L4 - Gas"), the active one marked; VIN
  and its verification result when present. Top-bar switcher shows the active vehicle and lists the others.
- **Actions:** add vehicle — cascading searchable comboboxes year → make → model → trim → engine (each disabled
  until its parent is chosen, auto-picked when only one option); optional VIN field (17 chars, validated inline:
  length, no I/O/Q) with "Decode" → NHTSA decode shown as a field-by-field comparison with the picked vehicle
  (year/make/model/trim/engine: ✓ agrees / ✗ differs / – not in decode) and, when the catalogue match from the
  decode narrows to cars, "Use decoded vehicle" fills the pickers. VIN first is allowed: decoding with nothing
  picked offers to fill the pickers. Make active, remove (confirm), set home ZIP/radius.
- **Empty:** no vehicles → the home page is the garage with "Add your first vehicle" and the picker open; part
  number lookup still works without a vehicle.
- **Error:** combobox list fails → inline message in that field with Retry; NHTSA unreachable → inline under VIN
  ("Couldn't reach NHTSA — the vehicle can still be saved"); invalid VIN → inline, Decode disabled; decode returns
  NHTSA error codes → shown inline as a warning, not a blocker; picker combination with no car → inline.
- **Success:** saved vehicle appears in the list immediately and becomes active; the switcher updates; toast-free
  — the list itself is the feedback, with the new row briefly highlighted.

### 2. Find a part on my vehicle
- **Shows:** left: category tree for the active vehicle (category → subcategory), always visible (drawer on
  phones). Filter box at the top of the tree. Right: selected subcategory's diagrams as cards (diagram image +
  part count); selecting a diagram shows it large with its parts list (callout index, name, number).
- **Actions:** expand/collapse categories; filter — typing ≥2 chars searches part names/numbers/other names for
  this car and shows hits **nested under their category → subcategory** in the tree (counts per node; non-matching
  branches hidden), clicking a hit opens its diagram with the part selected; zoom/pan the diagram; click a callout
  number or a parts-list row → workflow 3.
- **Empty:** no active vehicle → prompt to pick/add one (link to garage); car with no catalogue data → "No
  diagrams for this vehicle yet" + hint that the catalogue is still being scraped; filter with no hits → "No parts
  match '<q>'" inside the tree; nothing selected yet → right pane hint "Pick a category on the left".
- **Error:** tree/diagram fetch fails → inline in that pane with Retry; diagram image fails → placeholder with
  the parts list still usable.
- **Success:** selection is highlighted in the tree, and the URL reflects car/subcategory/diagram so back/forward
  and reload work.

### 3. Confirm the part
- **Shows:** part number, title, other names, description, notes/positions/replaces when present, MSRP; the
  diagram it came from (or every diagram it appears in, for part-number entry) with its callout highlighted;
  part photos (part_images) as a gallery; fitment summary ("fits N vehicles").
- **Actions:** "See interchange" (→ 4), "Find in yards" (→ 5), "Change part" (back to the diagram / tree with
  the same selection), open photo full size, copy part number.
- **Empty:** no photos → "No photos for this part" muted line (diagram still shown); no diagram → photos only.
- **Error:** part not found → "Part not found" with a link back; fetch failure → inline Retry.
- **Success:** the page is the confirmation; the two proceed buttons are primary.

### 4. Interchange chart
- **Shows:** every vehicle the part fits, grouped make → model, each model row showing compressed year ranges
  ("2007–2010, 2012") and, expandable, the trims/engines per year; total vehicle count; the active vehicle marked
  if it's among them.
- **Actions:** expand a model; filter by make; "Find in yards" (→ 5); click a vehicle → its catalogue at this
  part (workflow 2 for that car).
- **Empty:** part fits nothing in the catalogue (orphan part) → explicit message.
- **Error:** fetch failure → inline Retry.
- **Success:** n/a (read-only view).

### 5. Find it in a yard
- **Shows:** yards within radius of home ZIP holding an interchangeable vehicle; home yard (US Auto Supply)
  pinned first, then by distance; per yard: name, distance, address, phone, map link, vehicle count; per vehicle:
  year make model trim, row, colour, arrival date ("3 days ago"), VIN, exact/likely pill (likely = the yard car is
  one of several catalogue trims/engines, not all of which use the part).
- **Actions:** change ZIP/radius inline (re-runs); toggle "exact only"; open map; sort vehicles by arrival.
- **Empty:** no yards in radius → "No yards within N mi of ZIP" + widen-radius button; yards but no matching
  vehicles → "None of the yards near you have one right now" + interchange count for context.
- **Error:** inventory service down (502) → inline "Yard inventory is unavailable right now" with Retry; bad ZIP
  → inline validation on the ZIP field.
- **Success:** results list; the summary line "27 vehicles at 1 yard".

### 6. Look up a part number
- **Shows:** a part-number box in the top bar, always present.
- **Actions:** enter a number (dashes/spaces ignored) → exact match goes straight to workflow 3; several matches
  (same number, several manufacturers) → a small chooser; prefix matches offered as suggestions while typing.
- **Empty:** no match → inline under the box "No part numbered X".
- **Error:** lookup failure → inline under the box.
- **Success:** navigation to the part page.

### 7. Browse a yard
- **Shows:** Yards list (from the top bar): each yard with location and vehicle count, home yard first; a yard's
  inventory sorted newest arrival first (year make model trim, row, colour, arrival, VIN, catalogue match state).
- **Actions:** filter by make/model/year (searchable comboboxes over the yard's own vehicles); click a vehicle
  with a catalogue match → its catalogue (workflow 2 for that car); "Add to garage" for a matched vehicle.
- **Empty:** yard with no vehicles → message with last-scraped time; filter with no hits → message + clear.
- **Error:** inventory service down → inline Retry.
- **Success:** n/a (read-only), except add-to-garage → the switcher updates.
